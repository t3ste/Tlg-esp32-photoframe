Agenda ToDo Color Scheme

The full-screen Agenda ToDo/Calendar mode (see the main project plan) renders todo.txt-format items on the panel, styled after webstonehq/tuxedo's color-coded terminal look. This firmware targets several very different e-paper panels — some with a handful of fixed colors, some grayscale-only — so tuxedo's palette can only be an inspiration, not a literal copy: it has to be re-derived per panel type from the colors actually available, while staying true to tuxedo's intent (which element gets emphasized, and how strongly).

This document records that derivation — tuxedo's own colors, what each supported board can actually display — and then the resulting, actually-shipping per-hardware color assignment for both the ToDo and Calendar columns, plus the configurable shared background and its collision-avoidance rule, with every color shown as an actual rendered swatch, not just a hex code (plain Markdown/GitHub cannot render inline colors, hence this page).

1. Tuxedo's own color scheme

Source: src/theme.rs in the tuxedo repo. Tuxedo ships five built-in themes (Muted Slate, Dawn, Nord, Matrix, Terminal); “Muted Slate” is the default (index 0, selected whenever no theme = line is set in the user's config). The table below is Muted Slate, restricted to the fields relevant to rendering a todo.txt line (tuxedo also defines UI-chrome colors — panel background, borders, status bar, selection highlight, search-match highlight — which have no equivalent in this firmware's single-purpose ToDo screen and are omitted).

Two things worth noting, since they directly inform the hardware-constrained assignment below:
  • Tuxedo itself reuses colors across closely-related fields: overdue, today, and pri_a are the identical red; due and pri_b are the identical amber. Tuxedo doesn't treat every concept as needing its own unique hue — it groups by urgency meaning. This firmware's palette is far more constrained than a 24-bit terminal, so the same grouping strategy is used deliberately below, not as a fallback compromise.
  • Tuxedo is a dark theme (light text on a near-black background). This firmware's overlay conventions are the opposite (black text on a white background, matching every existing overlay — weather bar, captions, battery badge). Colors are re-picked for legibility on white, not transplanted by RGB value.

2. Hardware color capability

From boards/boards.json and BOARD_HAL_DISPLAY_TYPE (components/board_hal/include/*.h). Seven boards are supported, but they reduce to exactly two distinct color capability profiles — every board in a profile is driven through the identical palette/dithering code in image_processor.c, so there is no per-board variation to document within a profile.

3. ToDo column — as implemented

Priority, +project/@context tags, and due-date urgency are colored independently within one row via image_processor_draw_text_runs() (image_processor.c) — a sibling to image_processor_draw_text() that colors each character from whichever image_processor_text_run_t {start, length, r, g, b} range covers its index, falling back to the row's default (body) color otherwise. agenda_renderer.c's build_todo_line() builds the display text (priority marker, body text, tags — never shown before this feature, since todo.c parses them out of item->text but nothing displayed them — then the due-date suffix) and tracks each segment's exact range as it goes. An item can carry both a priority marker and a due date, each with its own independent color.

Every priority letter A–D gets the same treatment on Spectra6: a full-strength background chip plus a text color picked for contrast against it, rather than mixing plain-colored text and chips per letter. This is deliberate, not just cosmetic — Spectra6 dithers any RGB value that isn't one of its 6 exact palette colors, so a softer/blended shade (an earlier version of this renderer used rgb(0,179,0) for a calmer green) can render as visual noise or vanish entirely instead of a solid fill; only the 6 exact hues are guaranteed to render solid. Priority C's chip uses white text, not black — confirmed live on real Spectra6 hardware that the panel's actual green ink prints noticeably darker than the sRGB (0,255,0) preview suggests, so black text on it reads poorly (unlike yellow for B, where black stays correct).

Grayscale (16-level) boards

No chromatic hue exists at all, and unlike the priority chips above, grayscale keeps its original plain-black treatment throughout — there was no legibility bug to fix here, and 16 gray levels aren't enough to give every one of these roles its own distinguishable fill without them blurring together.

todo.txt element Rendered Colors
Priority (any letter), +Project, @Context, plain body text Buy milk Plain black text, no chip (flips to white if the configured background is black)
Overdue (due 2026-09-01) Full inversion — white text on black chip
Due today (due 2026-09-10) Black text on a level-8 (136) gray chip
Due later / no due date (due 2026-09-20) Plain black text, no chip

Note: the on-screen font is a fixed monochrome bitmap font (Font24), so image_processor_draw_text()/_draw_text_runs() can only paint solid glyph pixels in one color per call — the chips above use a bold sans-serif purely to preview the color pairing on this page; actual panel text looks like the rest of this firmware's overlay text (plain, not bold).

4. Calendar column — as implemented

Up to two independent calendar sources (Calendar A / Calendar B — e.g. a private and a work calendar) are fetched, merged, and sorted by start time into one list. Events are grouped under a dashed day divider (weekday abbreviation + day number, e.g. “Fr 11.”) rather than repeating a date on every line, and a multi-day event is shown under every day it spans, not just its start day. This replaced an earlier per-row “today = yellow / later = blue” scheme entirely, which both had the same low-contrast yellow-on-white problem the ToDo column's due-today role had, and (with day-grouping) is redundant anyway — “today” is already obvious as the first group under the header.

Each event's color now depends only on which calendar it came from, not on today/later. Colors are always plain text with no background chip, on either a light or dark page background — an earlier version filled a chip behind the text on a light background, but live testing found that background distracting against the actual event rows, so both background choices now use the same plain-text treatment.

Source Spectra6 Grayscale
Calendar A 09:00 Team meeting 09:00 Team meeting — both sources render identically (plain black), no per-source distinction
Calendar B 18:00 Dinner

The day divider itself and both column headers (“TODO…”/“CALENDAR…”) always draw a solid fill in the page's body-text color, with the label/title text color computed for contrast against that fill — so on the default white page background they render as a black chip with white text, and on a black page background they invert to a white chip with black text.

5. Configurable shared background + collision avoidance

The ToDo/Calendar page background (agenda_bg_color, Web UI: Agenda → Appearance) is user-selectable per hardware profile, defaulting to white:

Profile Selectable backgrounds
Spectra6
White (default) Black Yellow Red Blue Green
Grayscale
White (default) Gray75 Gray50 Gray25 Black
(a curated 5-level subset of the full 16, not every gray level)

Every plain, no-own-fill text color above (body text, priority-other, due-later, +project, @context) is automatically swapped to a safe fallback (black on a light background, white on a dark one) if — and only if — it would otherwise exactly match the chosen background, so nothing can silently disappear. Elements that already draw their own background chip (priority A–D, due-today/overdue, the day divider, both headers) are unaffected by this rule, since their own fill already guarantees contrast against whatever page background is chosen.
